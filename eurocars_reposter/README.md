# Автопубликация Euro Cars

Сервис читает новые публикации `@eurocar_group` через Ваш рабочий Telegram-аккаунт и публикует в `@Euro_Cars_Official`. Он заменяет Telegram/WhatsApp ссылки, `@username`, email и номера телефонов на `@Boris_GlobalAuto`, сохраняя характеристики и цену авто. Медиаальбомы отправляются одним альбомом. Старые посты не импортируются; изменения ранее опубликованных постов не синхронизируются.

## Подключение Telegram

1. Создайте собственное Telegram-приложение на https://my.telegram.org/apps и получите `api_id` и `api_hash`.
2. На **своём компьютере** установите Python 3.10+, запустите `pip install -r requirements.txt` и выполните `python auth_local.py`. Программа спросит `api_id`, `api_hash`, телефон, код подтверждения и пароль двухфакторной защиты, если он включён. Значение `api_hash` при вводе не отображается.
3. На Mac новая строка сессии копируется прямо в буфер обмена и не отображается в Терминале. Вставьте её в закрытую переменную Railway `TG_SESSION`. Также задайте `TG_API_ID` и `TG_API_HASH` в Railway Variables. Никому не отправляйте эту строку, код подтверждения или пароль: строка даёт доступ к рабочему аккаунту. После добавления переменных Railway перезапустит сервис.
4. Рабочий аккаунт должен состоять в источнике и иметь право публиковать в целевом канале. По умолчанию `DRY_RUN=true`: сервис показывает заменённый текст в логах, но не публикует. Убедившись в результате на новом посте, измените Railway Variable `DRY_RUN` на `false`.

При развёртывании без переменных авторизации сервис ждёт их и не обращается к Telegram. `TG_SESSION` нельзя хранить в GitHub. Защищённые от копирования посты могут не переноситься. Старые контакты, нанесённые прямо на фото или видео, не изменятся. Сайты вне Telegram и WhatsApp код не заменяет; проверьте первый пост на другие контактные данные. Для очень длинной подписи Telegram может потребоваться отдельное правило сокращения.

SQLite база предотвращает повторную отправку в рамках одного запуска, но файл в стандартном контейнере Railway может сбрасываться при новом развёртывании. Сервис обрабатывает новые события, не загружая старые посты, поэтому обычный перезапуск не републикует историю.

# HubOfCandy reposter

This worker watches one Telegram source through a dedicated user session, replaces recognized contact details with `CONTACT`, and publishes each post or album to all `DESTINATION_CHANNELS`. Each destination receives an independent copy. It does not import older posts by default; set `REPOST_SINCE` explicitly to the UTC date and time from which publishing should begin.

## Railway variables

- `TG_API_ID`, `TG_API_HASH`: API credentials for your Telegram application.
- `TG_SESSION`: a **new, dedicated** StringSession generated by `python auth_local.py` on your own computer. Do not reuse the session of another deployment.
- `SOURCE_CHANNEL`: source channel username without `@`.
- `DESTINATION_CHANNELS`: comma-separated destination channel/chat usernames.
- `CONTACT`: replacement contact such as `@your_username`.
- `REPOST_SINCE`: ISO 8601 UTC timestamp such as `2026-10-01T00:00:00+00:00`.
- `NEW_DESTINATIONS_SINCE`: optional alternate timestamp for additional destinations.
- `DRY_RUN=true`: preview transformed posts in Railway logs; switch to `false` only after checking the destinations and preview.
- `DB_PATH=./private/reposted.sqlite3`: use a persistent Railway volume for durability across redeployments.

The worker waits without connecting to Telegram until all required variables are supplied. Contact text inside images and videos is unchanged. Ensure the account can read the source and publish to each destination. Never commit API secrets or session strings to GitHub.
